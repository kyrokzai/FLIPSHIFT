# Безопасность и персональные данные Talent Agent

Состояние на 19.11.2026. Документ отделяет то, что защищено сейчас, от того, что нужно сделать до LIVE с настоящими кандидатами.

## Модель угроз текущей версии

Серверной базы и аккаунтов нет. Данные кандидатов хранятся только в браузере работодателя. Сервер получает:

| Запрос | Что передаётся | Хранится на сервере |
|---|---|---|
| Создание вакансии | текст запроса работодателя | нет |
| Чтение файла резюме | файл, только если браузер не смог прочитать его сам | нет, обработка в памяти |
| Анализ резюме | текст резюме, только если подключена модель | нет |
| Реплика ИИ-собеседника | ответы кандидата без контактов, только если подключена модель | нет |

Без языковой модели резюме и ответы Skill Challenge на сервер не отправляются — это проверяет сквозной тест.

## Что защищено сейчас

- Проверка входных данных схемами Zod, ограничения размера запросов и файлов.
- Ограничение частоты запросов по IP.
- Заголовки безопасности, закрытие от поисковых роботов, ответы API не кэшируются.
- Ошибки API не раскрывают внутренние сообщения.
- В журнал действий не записываются тексты резюме, ответы кандидатов, контакты, ключи и длинные токены; имена кандидатов подставляются только при показе.
- Перед отправкой в модель из текста вырезаются телефоны, почта, ссылки на мессенджеры и строки с личными признаками.
- Встроенная оценка резюме и проверки навыков не использует защищённые признаки.
- Согласие кандидата на Skill Challenge фиксируется с версией текста, временем и указанием, кто вносит ответы.

## Ограничения, о которых нужно помнить

- **Журнал браузера — не аудит.** Его можно очистить вместе с данными браузера, он не виден другим сотрудникам. В интерфейсе это написано.
- **Нет разграничения доступа.** Любой, кто пользуется тем же браузером, видит вакансии и кандидатов.
- **Согласие отмечает работодатель.** Пока кандидат не проходит проверку по своей ссылке, платформа не может доказать, что согласие дал именно он.
- **Данные не синхронизируются.** На другом устройстве их нет.

## H6. Ссылка на интервью — требования до запуска

Публичные ссылки для настоящих кандидатов не выпускаются, пока не выполнено всё ниже.

| Требование | Решение |
|---|---|
| Хранение | серверная база в Республике Казахстан |
| Доступ работодателя | авторизация, организации, роли owner, recruiter, hiring_manager |
| Токен приглашения | не менее 128 бит случайности (`crypto.randomBytes(32)`), в URL — только токен |
| Хранение токена | только хеш SHA-256; сам токен показывается работодателю один раз |
| Срок действия | по умолчанию 7 дней, задаётся работодателем |
| Отзыв | работодатель может отозвать ссылку в любой момент |
| Попытки | ограничение числа открытий и ответов, блокировка при переборе |
| Чужие интервью | приглашение привязано к кандидату и организации; сервер проверяет оба |
| Логи | токены и ответы не пишутся в логи и аналитику |
| Согласие | кандидат видит компанию, вакансию, цель, условия обработки и даёт согласие сам; фиксируются версия текста и время |
| Отказ | кандидат может отказаться; отказ не ведёт к автоматическому отклонению |
| Удаление | удаление по запросу кандидата и по истечении срока хранения |
| Запрещено | анализ голоса, эмоций, внешности и скрытый анализ личности |

Тесты H6 должны покрывать: неверный токен, просроченный токен, отозванный токен, чужую организацию, перебор попыток, отсутствие токена в логах.

## Многопользовательская версия

Изоляция организаций реализуется на сервере, не во фронтенде:

1. `organization_id` в каждой таблице с данными организации.
2. Контекст доступа берётся из сессии на сервере, никогда из запроса клиента.
3. Row Level Security в PostgreSQL как второй слой.
4. Автотесты: пользователь одной организации не может прочитать или изменить данные другой.

## Закон РК «О персональных данных и их защите» № 94-V

Это не юридическое заключение; перед LIVE нужна проверка юристом.

- **Ст. 7, 8** — согласие субъекта, подтверждаемое, с указанием оператора, срока, передачи третьим лицам и перечня данных.
- **Ст. 7, п. 3-1** — публичное резюме не освобождает от обязанности доказать законность сбора.
- **Ст. 12, п. 2** — хранение персональных данных в базе на территории РК.
- **Ст. 16** — трансграничная передача только при должной защите или с согласия. Языковые модели работают за пределами РК: передача резюме и ответов в модель требует согласия кандидата.

## Чек-лист перед LIVE

1. Хостинг базы в РК выбран и проверен.
2. Основания обработки и трансграничной передачи подтверждены юристом.
3. Тексты согласий и политика конфиденциальности утверждены.
4. Сроки хранения определены, удаление реализовано.
5. Доступ ограничен по организациям, тесты изоляции проходят.
6. Загрузка файлов проверена: размер, тип по содержимому, отказ от исполняемых и защищённых форматов.
7. Передача данных в модель минимизирована и согласована.
8. Безопасность ссылок на интервью проверена по таблице выше.
