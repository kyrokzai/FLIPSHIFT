## Минимальная миграция для P1

H6 и многопользовательская версия H5 и H7 невозможны без сервера. Минимальный набор:

1. **База данных** PostgreSQL в Казахстане (закон № 94-V, ст. 12) — выбор хостинга за владельцем.
2. **Авторизация** работодателей и **организации** с ролями owner, recruiter, hiring_manager.
3. **Схема**: organization, member, vacancy, candidate, challenge, interview_invite (хеш токена, срок, отзыв, счётчик попыток), interview_answer, consent, event, pipeline_transition.
4. **Изоляция**: `organization_id` в каждой таблице, проверка прав на сервере в каждом запросе и Row Level Security в базе.
5. **Перенос**: черновики из браузера переносятся в аккаунт при первом входе. Формат хранилища уже типизирован схемами Zod — их можно переиспользовать как контракт API.

Подробности безопасности — в [TALENT-SECURITY.md](TALENT-SECURITY.md).

## Порядок дальнейших работ

1. Решение владельца: хостинг базы в РК, подключение языковой модели и бюджет.
2. H6: серверная основа (база, авторизация, организации), затем токены приглашений и страница кандидата. До этого — только DEMO.
3. H7: этапы, история переходов, заметки, напоминания внутри приложения. Email — после разрешённой интеграции.
4. H8: профиль компетенций из анализа резюме и Skill Challenge — четыре отдельные оси: наличие доказательства, уровень, релевантность, уверенность.
5. H9: только с проверяемыми источниками; без них — «Недостаточно данных для достоверной оценки рынка».

## Откат

- Весь P0 — отдельная ветка и отдельный PR; `main` и production не изменялись.
- Новые поля хранилища имеют значения по умолчанию: опубликованная версия читает новые вакансии, новая — старые (проверено тестом `tests/unit/storage-compat.test.ts`). Откат версии не ломает сохранённые данные; новые поля старая версия просто не показывает.
