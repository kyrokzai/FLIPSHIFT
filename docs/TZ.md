# FORMIQ TALENT AGENT — техническое задание

| | |
|---|---|
| Продукт | FORMIQ TALENT AGENT (кратко — Talent Agent) |
| Разработчик | FORMIQ |
| Слоган | Intelligence in Motion |
| Версия документа | 1.1 от 17.11.2026 |
| Состояние | H1–H2 реализованы; пилот подбора по одной вакансии реализован досрочно; H3–H7 запланированы |

Документ заменяет прежнее описание репозитория (браузерная игра FLIPSHIFT) и является единственным актуальным ТЗ.

## 1. Назначение

Talent Agent — универсальная ИИ-платформа поиска и подбора сотрудников для бизнеса любой отрасли. Работодатель описывает потребность обычными словами, платформа превращает её в структурированную вакансию, помогает найти и оценить кандидатов и готовит шорт-лист. Окончательное решение о найме всегда принимает работодатель.

Основной рынок — Казахстан. Интерфейс на русском языке, валюта по умолчанию — тенге.

## 2. Пользователи

| Роль | Что делает |
|---|---|
| Работодатель без аккаунта | Создаёт черновик вакансии через ИИ, редактирует, копирует текст |
| Владелец организации | Управляет организацией, участниками, вакансиями и данными кандидатов |
| Рекрутер организации | Ведёт вакансии, импортирует резюме, работает с воронкой |
| Кандидат | Даёт согласие и проходит предварительное ИИ-интервью по ссылке |

## 3. Основной сценарий

Работодатель пишет: «Мне нужны два бариста в Астане, зарплата 300 000 тенге, график 5/2». Платформа должна:

1. Понять запрос.
2. Уточнить недостающие требования.
3. Сформировать структурированную вакансию.
4. Позволить работодателю изменить условия.
5. После подтверждения помочь запустить поиск кандидатов.
6. Анализировать доступные резюме.
7. Проводить предварительные ИИ-интервью с согласия кандидатов.
8. Формировать шорт-лист и рекомендации для работодателя.

Шаги 1–4 реализованы (этап H2). Шаги 5–8 — этапы H3–H7.

## 4. Опорные сценарии

Оба сценария покрыты автоматическими тестами.

**Сценарий 1 — мебельная компания.** Астана. Менеджер по активным продажам готовой мебели и мебели на заказ. Самостоятельный поиск клиентов, B2B-продажи, переговоры, заключение сделок. Работодатель рассматривает разные варианты оплаты — платформа предлагает выбрать несколько схем (оклад + %, только %, фиксированный оклад, по договорённости) и затем уточняет сумму или вилку.

**Сценарий 2 — кофейня.** Астана. Два бариста. Зарплата 300 000 ₸, график 5/2, опыт необязателен. Обязанности: приготовление кофе, работа с гостями, кассой, чистота рабочего места. Предварительное ИИ-интервью включено.

## 5. Функциональные требования

### 5.1. Создание вакансии через ИИ (H2 — реализовано)

- Поле свободного ввода на главной странице. Регистрация не требуется.
- Разбор запроса: должность, количество сотрудников, город, тип бизнеса, оплата (сумма, вилка, валюта, период, схема), график, занятость, формат работы, опыт, обязанности, требования, условия, ИИ-интервью.
- Пока работодатель печатает, под полем показывается, что уже понято.
- Уточняющие вопросы задаются только по незаполненным полям. Ответ — кнопкой или свободным текстом; вопрос можно пропустить.
- Правки свободным текстом: «измени зарплату на 350 тысяч и график 2/2».
- Ручное редактирование всех полей вакансии.
- Подтверждение вакансии возможно, когда указаны должность и город (или удалённый формат). Подтверждённую вакансию можно вернуть в черновик.
- Текст вакансии копируется для самостоятельного размещения.
- Черновики без регистрации хранятся в браузере работодателя и перечислены в разделе «Мои вакансии».

### 5.1a. Пилот подбора по одной вакансии (реализовано досрочно, 17.11.2026)

Приоритеты изменены ради демонстрации первому заказчику: полный сценарий одной вакансии важнее аккаунтов и базы.

- Поисковые запросы по вакансии и ссылки на поиск резюме на площадках под учётной записью работодателя.
- Реестр источников с пятью классами доступа: доступно без оплаты, нужен аккаунт работодателя, нужен OAuth / API, нужен платный доступ, недоступно или запрещено. Основания — в [SOURCING.md](SOURCING.md).
- Режим поиска с помощью агента: автоматического сбора страниц нет; работодатель ищет сам и добавляет резюме.
- Импорт резюме (PDF, DOCX, TXT, текст) с названием источника и ссылкой на оригинальный профиль.
- Анализ: профессиональные сведения из резюме, сравнение с вакансией по критериям, дословные выдержки как подтверждение, итоговое соответствие в процентах.
- Шорт-лист до пяти кандидатов с соответствием от 60% и объяснением; порог — рекомендация.
- Вопросы для предварительного интервью: общие по вакансии и личные по пробелам резюме.
- Статусы шагов: успешно, ошибка, требуется доступ, не подключено, ожидает, выполняется.
- Режимы DEMO и LIVE: у каждого кандидата свой режим, списки и шорт-листы раздельные.
- Без языковой модели резюме читается и анализируется в браузере и на сервер не передаётся.

Частично закрывает этапы H4 (анализ резюме), H6 (DEMO) и H7 (подготовка источников). Не входит: аккаунты, серверная база, автоматическое ИИ-интервью, коннекторы API.

### 5.2. Аккаунты и организации (H3)

- Регистрация и вход (Better Auth), организации, роли «владелец» и «рекрутер», приглашения.
- Сохранение вакансий в аккаунте, перенос черновиков из браузера.
- Кабинет работодателя с разделами: Мои вакансии, Кандидаты, ИИ-интервью, Воронка найма, Аналитика, Настройки.
- Доступ к данным кандидатов — только после входа и только в пределах своей организации.

### 5.3. Резюме и оценка кандидатов (H4)

- Ручной импорт резюме (PDF, DOCX, текст).
- Scout Agent структурирует опыт и навыки и оценивает соответствие вакансии с объяснением: что совпало, чего не хватает, что уточнить.
- Оценка — рекомендация. Автоматического отказа кандидату нет.

### 5.4. Предварительные ИИ-интервью (H5)

- Интервью проходит по персональной ссылке и начинается только после явного согласия кандидата. Кандидат заранее знает, что говорит с ИИ.
- Вопросы строятся по вакансии. Итог — краткое резюме ответов для работодателя.
- Кандидат может отказаться; отказ не становится причиной автоматического отклонения.

### 5.5. DEMO и LIVE (H6)

- **DEMO** — полноценный интерактивный сценарий с вымышленными кандидатами: анализ резюме, интервью, шорт-лист. Все данные явно помечены как демонстрационные.
- **LIVE** — настоящие вакансии и кандидаты, ручной импорт резюме, разрешённые интеграции, интервью с согласия.
- Демонстрационные и настоящие данные не смешиваются.

### 5.6. Источники кандидатов (H7)

- Подключаются только официальные интерфейсы площадок и только с учётной записью самого работодателя.
- Автоматический сбор страниц, обход CAPTCHA и ограничений площадок не используются.

## 6. Архитектура ИИ-агентов

Пять агентов — роли внутри одного приложения с общей инфраструктурой, а не пять отдельных сервисов.

| Агент | Задача | Этап |
|---|---|---|
| Orchestrator Agent | Принимает запрос, собирает вакансию, распределяет задачи | H2, работает |
| Sourcer Agent | Поиск кандидатов через разрешённые источники | H7 |
| Scout Agent | Анализ резюме и навыков | H4 |
| Interviewer Agent | Предварительное интервью | H5 |
| Coordinator Agent | Этапы найма, коммуникации, собеседования | H6 |

Правила экономного использования модели:

1. Всё, что можно сделать кодом, делается кодом: разбор по справочникам, уточняющие вопросы, проверка защищённых признаков, форматирование.
2. LLM вызывается один раз на свободное сообщение. Ответы кнопками модель не вызывают.
3. Постоянная часть инструкций кэшируется на стороне поставщика.
4. Результаты анализа резюме сохраняются и не пересчитываются без причины.
5. Если модель недоступна, платформа продолжает работать на встроенном движке.

Подробности — в [ARCHITECTURE.md](ARCHITECTURE.md).

## 7. Интерфейс

- Стиль FORMIQ: светлая основа, графитовые элементы, умеренные золотые акценты. Золото используется как сигнал «ИИ что-то понял» и для фокуса.
- Минимум кнопок: на каждом экране одно главное действие.
- Полная адаптация под iPhone: поля от 16 px (без автоувеличения), области нажатия от 44 px, учёт безопасных зон экрана, отсутствие горизонтальной прокрутки.
- Русский язык интерфейса. Тексты описывают действие прямо: «Собрать вакансию», «Подтвердить вакансию».
- Доступность: навигация с клавиатуры, видимый фокус, подписи для экранных дикторов, учёт настройки «уменьшить движение».

## 8. Правила работы с людьми и данными

Эти правила обязательны для всех этапов.

1. **Решение за работодателем.** ИИ готовит данные и рекомендации; нанимать или нет — решает человек.
2. **Защищённые признаки не используются.** Пол, возраст, национальность и происхождение, религия, семейное положение, внешность, состояние здоровья не попадают в вакансию и не участвуют в оценке. Если работодатель называет такое условие, платформа исключает его и объясняет причину.
3. **Интервью — только с согласия.** Согласие фиксируется до начала интервью.
4. **Никакой имитации.** Платформа не изображает отправленные сообщения, поиск на реальных площадках или проведённые собеседования. Если функция ещё не готова, интерфейс говорит об этом прямо.
5. **Только разрешённые источники.** Без обхода CAPTCHA, ограничений площадок и правил доступа к персональным данным.
6. **Персональные данные.** Хранение данных кандидатов — на территории Казахстана, с согласием каждого кандидата (закон № 94-V, ст. 7, 8, 12, 16; см. [SOURCING.md](SOURCING.md)). Изоляция организаций, серверная проверка прав на каждый запрос, минимизация данных, отсутствие персональных данных в журналах, удаление по запросу. Обработка должна соответствовать законодательству Республики Казахстан о персональных данных; юридическая проверка — до запуска LIVE.
7. **Секреты не хранятся в Git.** Ключи — только в переменных окружения.

| Слой | Технология | Версия | Состояние |

Результат проверки совместимости (17.11.2026):

- TypeScript 7.0 пока не поддерживается `typescript-eslint` (требуется < 6.1), поэтому выбран TypeScript 6.0.3.
- Better Auth 1.7 поддерживает Next.js 16, React 19 и Drizzle ORM 0.45.2+ — конфликтов для H3 нет.
- SDK Claude поддерживает Zod 4.
- `@playwright/test` закреплён на версии, совпадающей с установленным браузером.
